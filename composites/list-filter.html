List filter · without Advanced (all dimensions inline)

The default. When a list has only a handful of dimensions, every quick filter fits in the toolbar — no Advanced trigger, no spacer. It starts empty (no chips — an empty applied-filters row renders nothing). Type a term or pick Status / Region, then click Search to commit (principle 14 — nothing filters on change). Each committed criterion becomes a removable chip.

Pick Status / Region and click Search — chips build up from nothing

List filter · with Advanced (overflow dimensions in a sheet)

When a list has many dimensions, only the primary quick filter (Status) stays inline; the rest live in an Advanced filter sheet opened by the funnel trigger that condition-band__spacer pushes to the right edge. Click Advanced to open the sheet, choose criteria, then Apply — the sheet's filters surface as chips beside the inline one, so the active query stays fully visible.

Open Advanced, pick Region / Priority / Plan, Apply — chips appear from nothing

Search input · exact structure reference

The leading magnifier MUST be wrapped in .search-input__icon (a <span>), never a bare <svg> inside .search-input. A bare svg renders unsized and floods the bar. The .input gets padding-inline-start: space-8 via CSS to make room for the icon.

The magnifier is wrapped in .search-input__icon — the only correct structure — and the Search button carries the same glyph (never a funnel).
